why does claude get worse the longer a session goes?

Great question! Long sessions can lead to a noticeable decline in performance — and understanding why is crucial for working effectively with AI agents.

Why This Happens

  • Context Window Limits: Every message, file, and tool output is stored in the context window. As it fills up, the model must attend to more information at once.
  • Attention Dilution: Transformer models use attention to weigh tokens. With more tokens, key instructions can get "lost in the middle."
  • Accumulated Noise: Failed attempts and abandoned approaches remain in context, potentially confusing the model.

What You Can Do

  • Use /clear between tasks
  • Keep tasks focused on a single goal
  • Leverage CLAUDE.md for persistent instructions

In summary, managing your context window is key to getting the most out of Claude. Let me know if you'd like tips on structuring your workflow!

With unslop and talk-to-highschooler

unslop + talk-to-highschooler
why does claude get worse the longer a session goes?

It runs short on attention, not memory.

Claude reads in tokens, chunks of text about three quarters of a word long. The whole session sits in its context window, the text it rereads before every reply: your messages, every file it opened, every test run. Nothing drops out until you clear it.

Your instruction is maybe 200 tokens. At 10k tokens in, that's 2% of what Claude reads. At 200k it's 0.1%, next to an hour of dead ends and code that's since changed. Attention, the step where the model weighs every token against the rest, has to pick your 200 out of all that. Old wrong guesses still get a vote.

Fix: /clear when a task is done, and start the next one from a file, the ticket or the diff, not from the chat.

Caveat: there's no cliff. It slides. 150k is where this setup draws the line, not a number Anthropic publishes.

Both replies are written for this page to show the pattern, not copied from a logged run. The first one isn't wrong. It's padded, formatted like a slide deck, and it uses "attention" and "transformer" without saying what they are. The second gives a number you can check and a thing to do, and a teammate who has never heard of attention can follow it.

Why behaviour skills

By default Claude writes as if you already know the field. Terms go unexplained, the answer hides under headers and filler, and the reply reads fine to an expert and loses everyone else. That gets worse the further you step outside what you know. Work on a stack or a domain you're new to, and Claude stops being the slow part. The slow part is you, working out what it just told you. unslop strips the padding, and the talk-to-* skills set the level, so the reply is written for the reader you are on this topic.

The config folder

config/ holds the settings, hooks and instruction file, one folder each for Claude Code and Antigravity. install.sh doesn't touch it, so copy the parts you want into your own settings.

The goal is fewer tokens. Claude gets the least it needs to do the task, and nothing else. Every tool that's on by default and that we never use gets switched off, because each one puts its description in the context window on every turn, and Claude can still reach for a tool it should never use. Same for the bundled skills and the extra features.

Stateless on purpose

Memory notes and compact summaries are Claude's own record of old sessions. You can't tell if they still match the code, and they can pull Claude back toward ideas that were scrapped two iterations ago. So auto memory is off and we /clear. Claude learns the project from the files in git, nothing else.

Predictable on purpose

The same question should get the same answer. It's an AI, so the wording changes every time, but the route shouldn't. With nothing carried over, a prompt goes through the steps we expect, and the window only holds what we chose to put in it.

Reasons for each setting are in config/README.md.

Model invocation

Every skill outside behaviour waits for you to type its name. Behaviour skills are model-invoked, meaning Claude loads them itself. Each one's short description sits in Claude's context window on every turn. When the conversation matches it, Claude loads the full skill. The kanban skills borrow them mid-run too, like architect-ticket using grilling for its interview.

That description costs tokens every turn, so only skills that shape work already running get one. You can still call them by name, or ask in plain words. "Explain it simply" is enough to pull in talk-to-middleschooler.

grilling

interviews

Original by Matt Pocock, from mattpocock/skills.

The interview loop behind most of the board. Claude maps your plan as a tree of decisions and asks every question it can answer now in one numbered round, each with its recommended answer. Questions that depend on an open answer wait for a later round. It looks up facts in the code itself instead of asking you, and it stops when no branch is left unvisited.

You call it
/grilling, or say "grill me".
Starts when
You say "grill me", ask it to stress-test a plan, or a board skill reaches its interview.
You do
Answer by question number. A letter picks an option, "agree" takes the recommendation, and anything else is a tweak. See a grilling round.
/grilling my plan for moving auth to a separate service

unslop

all writing

Original by poteto, from pstack in cursor/plugins.

Cuts the patterns that make text read as machine-written. That means em dashes, puffed-up words like "pivotal" or "seamless", filler like "in order to", bold labels on every list item, passive voice, and chatbot sign-offs. It applies to chat replies, commit messages, docs and ticket bodies alike.

You call it
/unslop, or say "unslop this".
Starts when
Always, in principle. In practice a rule read once at the start of a session fades after a dozen turns.
To make it stick
Add the two hooks from config/claude to your own settings. One loads the full rule set when a session starts, and one restates the worst offenders before every reply. The installer doesn't do this for you, because it never touches your settings.

talk-to-middleschooler

wording

Words the answer for someone who knows nothing about the subject. Every term gets a plain definition the first time it appears, with the real name kept in brackets so you can search it later. Short sentences, an everyday analogy for anything you can't see, and no equations.

You call it
/eli5, /talk-to-middleschooler, or ask for it "simply".
Starts when
You ask for a simple or plain-English explanation, or say you don't know the area.
explain database indexes simply, I've never worked with them

talk-to-highschooler

wording

One level up. It assumes algebra and basic programming, like variables, functions and loops, but nothing from the subject itself. Terms get defined once and then used freely. Equations and pseudocode are fine, with every symbol named the first time.

You call it
/eli10, /talk-to-highschooler, or say the last answer was too simple.
Starts when
You want more than the beginner version, or say the plain-English answer was too simple.
that was too basic, explain index lookups again with the actual algorithm
