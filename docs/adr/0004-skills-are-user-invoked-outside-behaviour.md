# ADR-0004: Skills are user-invoked outside `behaviour/`

**Decision:** Every Skill outside `behaviour/` MUST set `disable-model-invocation: true` and use a human-facing description, except `kanban/grill-docs`, `kanban/amend-pcr`, `kanban/pr-ticket` and the six stations `kanban/architect-ticket`, `kanban/implement-ticket`, `kanban/refactor-ticket`, `kanban/unit-test-ticket`, `kanban/execute-ticket` and `kanban/review-diff`, which MUST be model-invoked.

**Reason:** User invocation keeps the choice of work with the user and keeps descriptions out of context until needed. Behaviour Skills are borrowed by work already running, as are `grill-docs` for interviews, `amend-pcr` for blocked conventions and `pr-ticket` for PRs. The six stations must be reachable through the Skill tool so each `tdd-ticket` subagent loads its own instructions. Reading every station in the orchestrator and copying its full text into each starting prompt adds those instructions to the orchestrator's context. Short model-facing descriptions cost context on every turn but allow the full station instructions to load in the subagent that uses them. This is a context-use experiment, with no measured reduction or halt-rate improvement yet.

**Consequence:** `tdd-ticket` remains user-invoked. It invokes `architect-ticket` and `pr-ticket` through the Skill tool in its own session and directs each later station's fresh subagent to invoke its skill through that tool. It never reads or copies station instructions into subagent prompts. The wrapper, model choices, halt rules and resume answers still apply. An unavailable skill causes a halt rather than a fallback file read. The six stations can also be invoked by Claude outside `tdd-ticket`; their own approval gates still bind. All other handoffs pass through artifacts or bundled reference files. A new exception needs this record amended.

**Date:** 2026-11-27
