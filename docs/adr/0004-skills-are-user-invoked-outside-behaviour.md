# ADR-0004: Skills are user-invoked outside `behaviour/`

**Decision:** Every Skill outside `behaviour/` MUST set `disable-model-invocation: true` in its frontmatter, and its `description` MUST be written for a human reader rather than as invocation triggers. Only a Skill in `behaviour/` may be model-invoked, plus `kanban/grill-docs`, `kanban/amend-pcr` and `kanban/pr-ticket`, and only `kanban/tdd-ticket` may run another Skill by reading its `SKILL.md`.

**Reason:** The alternative was model-invoking everything, which buys two things: Claude can fire a Skill on its own, and one Skill can reach another by name. Both lost. Autonomous firing hands Claude the decision about what work happens next, which is the decision most worth keeping, and every model-facing description sits in the context window on every turn whether or not it is used. Twenty-two of them is real load for Skills that mostly open a session. A `behaviour/` Skill is different in kind. It is borrowed by work already running rather than starting any, so `unslop`, `gloss-me`, and the two Talk-to Skills have to be reachable from inside another Skill, and their descriptions earn what they cost. `grill-docs` is borrowed the same way, as the interview for `new-ticket`, `map-epic`, `architect-ticket`, and `brainstorming`, so every grill records what it settles. It stays in `kanban/` rather than moving to `behaviour/` because it owns the record format, and four stations there read that file through `../grill-docs/`. In `behaviour/`, those links would leave their Category and break in the Claude plugin, per ADR-0007. `amend-pcr` is loaded the same way, by the session a PCR blocks, so the ripple and the verdict land where the work is instead of in a separate session. A blocked Skill will reach for it to unblock itself, so the guard lives inside it instead of in its reachability. It writes nothing to `docs/pcr/` until the user approves the listed changes. `pr-ticket` is reachable so every PR goes through it. Starting every station by hand then cost more than it protected: after the architect grill settles a ticket, each later session either asks nothing or asks what the grill already answered. The fix this record predicted was a router, and `tdd-ticket`, the orchestrator, is that router. It was weighed against making the stations model-invoked with short descriptions, which lost because it puts every station back in the context window and lets Claude start work anywhere. The router reads each station's `SKILL.md` and hands the full text to a fresh subagent in its starting prompt, so the stations stay user-invoked, cost nothing per turn, and run only inside a `tdd-ticket` session the user started.

**Consequence:** Cross-Skill invocation is not available outside `behaviour/`, `grill-docs`, `amend-pcr`, `pr-ticket` and `tdd-ticket`, so every other handoff has to run through an artifact. The `kanban/` chain passes an epic issue, a ticket, and a red branch; `brainstorming` ends by naming a route instead of taking it; a Skill blocked by an ADR stops and names it rather than opening `challenge-adr`, while one blocked by a PCR loads `amend-pcr`. A new Skill that needs another Skill's logic reads a bundled file or gets restructured, and never gets a reach clause added to its description. `tdd-ticket` reaches stations only through their files, never by name through the Skill tool, and a subagent it starts gets the station's text in its prompt rather than a path to go find. Another exception or a second orchestrator needs this record amended, not a quiet description change.

The load moves rather than disappearing. The stations still have nothing in the window to remind me they exist, and remembering them is mine, except that `tdd-ticket` now remembers the chain for one ticket.

In a diff, a breach looks like a `SKILL.md` outside `behaviour/` other than `grill-docs`, `amend-pcr` and `pr-ticket` with no `disable-model-invocation` line, a description carrying trigger phrasing such as "Use when the user says", or a Skill other than `tdd-ticket` instructing Claude to run a non-`behaviour/` Skill other than `grill-docs`, `amend-pcr` or `pr-ticket`.
