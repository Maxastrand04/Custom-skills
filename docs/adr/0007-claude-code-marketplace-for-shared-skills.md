# ADR-0007: Claude Code marketplace for the shared skills

**Decision:** The repo MUST carry a Claude Code plugin marketplace at `.claude-plugin/marketplace.json` with one plugin, `max`, whose source is the repo root and whose `skills` list names each shared skill by path. The shared set is the skills the tutorial teaches: all of `kanban/`, `developer-tools/` minus `prune-skill`, and `behaviour/` minus `science-output`. `schoolwork/` and `archive/` MUST NOT be listed. `install.sh` stays as the second install path and the only one for Antigravity. This supersedes the "one install path" rule in ADR-0005.

**Reason:** AI Society members use these skills, and cloning a repo, keeping it in place, and running a shell menu was the main setup friction. Two commands inside Claude Code replace all of it, and `/plugin marketplace update` replaces `git pull`. One plugin rather than one per category, because the tutorial teaches the set as a whole and the kanban skills lean on `grilling`. The source is the repo root and not a copy per skill, because kanban skills read sibling files by `../<skill>/<file>`, and those paths only resolve if the category layout survives into the plugin cache. Personal skills stay tracked in git and are kept out by leaving them off the list, not by ignoring them, so they keep their history and still come with a fresh clone.

**Consequence:** Plugin installs prefix every skill with the plugin name, so members type `/max:grilling` where an `install.sh` user types `/grilling`. Plugin installs are copies, so ADR-0002's live editing holds only for `install.sh` users, which keeps that the author's path. A new shared skill needs a line in `marketplace.json` as well as a directory. A `../` path across categories would resolve after a flat `install.sh` and break in the plugin, so shared contracts must stay within one category. The plugin cache holds the whole repo, unlisted skills included, but only listed skills load.
