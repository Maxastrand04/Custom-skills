# Test File Schema

Every file generated by the `generate-test` skill must conform to this schema.

---

## Frontmatter

Each test file begins with a YAML frontmatter block containing exactly these four fields:

```yaml
---
source: <relative path to the source file under test>
test: <relative path to this test file>
source_sha: <short git SHA of the source file at generation time>
generated_sha: <short git SHA of this test file at generation time>
---
```

Field definitions:

- `source` — relative path to the source file this test file covers.
- `test` — relative path to this generated test file.
- `source_sha` — short git SHA of the source file at the time the test file was generated. Used to detect staleness.
- `generated_sha` — short git SHA of this test file at the time it was last regenerated.

No other frontmatter fields are permitted.

---

## Agent blocks

After the frontmatter, the file contains one or more agent blocks. Each block follows this format:

```
## Agent: <job>

**Job:** <job name>
**Targets:** <comma-separated list of symbol names from the source file>
**Cases:** <test case descriptions, or `pending`>
```

### Sub-fields

- `**Job:**` — the job name that identifies which agent runs this block (see Default jobs below).
- `**Targets:**` — symbol names extracted directly from the source file (function names, class names, method names, etc.). These are not invented — they must exist in the source file.
- `**Cases:**` — one or more test case descriptions supplied by the user. Cases are user-sourced only: no auto-generation and no empty placeholders are permitted. If the user has not yet provided cases for this block, write `pending` as the value (see Deferral marker below).

---

## Default jobs

The three default job names are:

- `unit` — isolated tests of individual symbols, no external dependencies.
- `integration` — tests that exercise multiple symbols or cross module boundaries.
- `behavior` — end-to-end or user-facing behavior tests.

The schema is extensible: custom job names are allowed alongside or instead of the defaults. Any string is a valid job name.

---

## Deferral marker

When a user skips providing cases for a block during the round-3 grill, write:

```
**Cases:** pending
```

A block with `cases: pending` is a valid placeholder. It signals that the block must be revisited before test generation runs. Agents must not generate tests for blocks marked `pending`.
